Redact before summarizing

Remove known private values before sending a support note to a model.

Offline demo + live modeDownload application ↓

What you will build

A support note repeats a customer email and account ID. Both values stay local while the model receives a redacted copy.

Output artifact

summary.json

Saved locally for you to inspect and use.

main.kujo

Source ↓
from common import load, save, config, request, require_result

let input := load("input.json")
mut redacted := input["message"]
assert(len(input["private_values"]) > 0, "Configure the private values first")
for value in input["private_values"] {
    assert(len(value) > 0, "Private values must not be empty")
    redacted = replace(redacted, value, "[REDACTED]")
}
for value in input["private_values"] {
    assert(contains(redacted, value) == 0, "A private value remains in the request")
}
# Keep the original input and private-value list out of the provider request.
let result := request(config(), "Summarize this redacted support note without guessing missing identities.", {"message": redacted}, "responses.json", load("schema.json"))
let data := require_result(result)
for value in input["private_values"] {
    assert(contains(data["summary"], value) == 0, "Output contains a known private value")
}
save("summary.json", {"redacted_input": redacted, "summary": data["summary"], "status": "needs_review"})
print("Saved summary.json; configured private values were not sent.")

Run it locally

Start offline.

Install Kujo, download the application, then run these commands from your download directory.

unzip redacted-summary.zip -d redacted-summary
cd redacted-summary
kujo run main.kujo

The ZIP includes main.kujo, common.kujo, input, schema, response fixtures and README.md. Run inside its extracted directory. No key or network request is needed in offline mode.

Read the shared request policy ↗

Offline responses are authored test fixtures. They demonstrate control flow, not live model quality.

How it works

  1. Replace every occurrence of the configured private values locally.
  2. Send only the redacted message, without the private-value list.
  3. Reject an output containing a known private value and save a reviewable summary.

Try a failure. Then recover.

Put the original email into the response fixture. The output check rejects it. Restore the redacted fixture and rerun to recover.

Use a fresh extraction to restore the original fixtures. A failed run does not make an older output file current; check the exit status before consuming results.

Connect a live provider

Live mode sends your input to the configured provider and may cost money. Choose an OpenAI-compatible endpoint and model you can access, then set credentials in your environment. The example sends at most 1,024 output tokens per request and normally allows two attempts. The batch and regression examples apply that limit per item.

export KUJO_WORKFLOW_MODE=live
export KUJO_AI_ENDPOINT=https://your-provider.example/v1/chat/completions
export KUJO_AI_MODEL=your-model
# Set KUJO_AI_KEY securely in your environment.
kujo run main.kujo

Live transport was tested against a controlled local HTTP server, including failure and timeout cases. No paid provider call or claim about model quality is part of this demo.

Make it yours

Replace the message and private_values together. Include every value that must stay local, with longer overlapping values first. Inspect the redacted request before adapting this to real customer data.

Know the boundary

This exact-value filter is not a general detector of personal information. Unlisted, encoded or inferred details can pass through. The original input remains on disk; use appropriate local access controls.
