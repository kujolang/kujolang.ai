Resumable batch processor

Classify records, save checkpoints and continue after interruption.

What you will build

Three support records produce billing, account and technical labels. Completed record IDs survive a stopped process.

main.kujo

Source ↓
from common import load, save, config, request, require_result

let input := load("input.json")
let signature := sha256(to_json(input))
mut checkpoint := {"input_hash": signature, "results": {}}
if file_exists("checkpoint.json") {
    checkpoint = load("checkpoint.json")
    assert(checkpoint["input_hash"] == signature, "Input changed. Use a new checkpoint directory.")
}
let cfg := config()
mut processed := 0
mut seen := []
for record in input["records"] {
    assert(!contains(seen, record["id"]), "Duplicate record ID")
    seen = push(seen, record["id"])
}
for record in input["records"] {
    if has_key(checkpoint["results"], record["id"]) == 0 {
        let result := request(cfg, "Classify this support message as billing, account or technical.", record, "responses-" + record["id"] + ".json", load("schema.json"))
        let data := require_result(result)
        checkpoint["results"][record["id"]] := data
        # Publish a complete checkpoint only after its contents are written.
        save("checkpoint.next.json", checkpoint)
        rename_file("checkpoint.next.json", "checkpoint.json")
        processed = processed + 1
        print("Completed " + record["id"])
        if to_string(processed) == env_or("KUJO_STOP_AFTER", "") {
            print("Stopped after a saved checkpoint; rerun to resume.")
            exit(3)
        }
    }
}
save("batch-results.json", checkpoint["results"])
print("Saved batch-results.json; completed records were not requested again.")

Run it locally

Start offline.

Install Kujo, download the application, then run these commands from your download directory.

unzip resumable-batch.zip -d resumable-batch
cd resumable-batch
kujo run main.kujo

The ZIP includes main.kujo, common.kujo, input, schema, response fixtures and README.md. Run inside its extracted directory. No key or network request is needed in offline mode.

Read the shared request policy ↗

Offline responses are authored test fixtures. They demonstrate control flow, not live model quality.

How it works

  1. Check that IDs are unique and the input matches any saved checkpoint.
  2. Request and validate one unfinished record at a time.
  3. Write a complete checkpoint and rename it before moving to the next record.

Try a failure. Then recover.

Run KUJO_STOP_AFTER=1 kujo run main.kujo. Exit code 3 means the first result was saved. Run again without that variable to finish; the first request is skipped.

Use a fresh extraction to restore the original fixtures. A failed run does not make an older output file current; check the exit status before consuming results.

Connect a live provider

Live mode sends your input to the configured provider and may cost money. Choose an OpenAI-compatible endpoint and model you can access, then set credentials in your environment. The example sends at most 1,024 output tokens per request and normally allows two attempts. The batch and regression examples apply that limit per item.

export KUJO_WORKFLOW_MODE=live
export KUJO_AI_ENDPOINT=https://your-provider.example/v1/chat/completions
export KUJO_AI_MODEL=your-model
# Set KUJO_AI_KEY securely in your environment.
kujo run main.kujo

Live transport was tested against a controlled local HTTP server, including failure and timeout cases. No paid provider call or claim about model quality is part of this demo.

Make it yours

Replace input.json.records with your batch. Live mode can process additional IDs without fixture files. Use a fresh directory when changing the input, schema or prompt. Run one worker per checkpoint directory.

Know the boundary

This is a single-process checkpoint pattern, not a distributed queue or a power-loss durability guarantee. A request interrupted before its checkpoint may be repeated.
