Source ↓
from common import load, save, config, request, require_result

let input := load("input.json")
# Build an allowlist of added lines directly from a unified Git diff.
mut path := ""
mut line := 0
mut allowed := []
for row in split(input["diff"], "\n") {
    if starts_with(row, "+++ b/") {
        path = substring(row, 6, len(row))
    } else if starts_with(row, "@@ ") {
        let header := split(row, " ")
        line = to_int(replace(split(header[2], ",")[0], "+", ""))
    } else if starts_with(row, "+") {
        allowed = push(allowed, path + ":" + to_string(line))
        line = line + 1
    } else if starts_with(row, " ") {
        line = line + 1
    }
}
let result := request(config(), "Review this Git diff for concrete correctness bugs. Report only added lines, or an empty findings list. Explain a triggering input and suggest a fix.", input, "responses.json", load("schema.json"))
let data := require_result(result)
mut accepted := []
mut rejected := []
for finding in data["findings"] {
    if contains(allowed, finding["path"] + ":" + to_string(finding["line"])) {
        accepted = push(accepted, finding)
    } else { rejected = push(rejected, finding) }
}
save("review.json", {"findings": accepted, "rejected_locations": rejected, "attempts": result["attempts"], "needs_human_review": true})
print("Saved review.json; inspect findings before posting or changing code.")

Run it locally

Start offline.

Install Kujo, download the application, then run these commands from your download directory.

unzip repository-review.zip -d repository-review
cd repository-review
kujo run main.kujo

The ZIP includes main.kujo, common.kujo, input, schema, response fixtures and README.md. Run inside its extracted directory. No key or network request is needed in offline mode.

Read the shared request policy ↗

Offline responses are authored test fixtures. They demonstrate control flow, not live model quality.

How it works

  1. Parse added-line locations from a unified Git diff.
  2. Ask for structured findings with reasons and suggested fixes.
  3. Separate findings with valid locations from invented locations.

Try a failure. Then recover.

Change the fixture finding to an unknown path or line. It moves to rejected_locations rather than appearing as an accepted finding. Restore the original response to recover.

Use a fresh extraction to restore the original fixtures. A failed run does not make an older output file current; check the exit status before consuming results.

Connect a live provider

Live mode sends your input to the configured provider and may cost money. Choose an OpenAI-compatible endpoint and model you can access, then set credentials in your environment. The example sends at most 1,024 output tokens per request and normally allows two attempts. The batch and regression examples apply that limit per item.

export KUJO_WORKFLOW_MODE=live
export KUJO_AI_ENDPOINT=https://your-provider.example/v1/chat/completions
export KUJO_AI_MODEL=your-model
# Set KUJO_AI_KEY securely in your environment.
kujo run main.kujo

Live transport was tested against a controlled local HTTP server, including failure and timeout cases. No paid provider call or claim about model quality is part of this demo.

Make it yours

Replace input.json.diff with the output of git diff --no-ext-diff --unified=3. Keep the review local until a person checks it. This parser covers ordinary text diffs, not combined merge diffs or binary patches.

Know the boundary

Location checks establish where a finding points. A person must still judge whether the bug and suggested fix are correct.
