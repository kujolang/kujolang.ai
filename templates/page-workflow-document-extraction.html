Document extraction pipeline

Turn invoice text into a validated record with source evidence.

Offline demo + live modeDownload application ↓

What you will build

An invoice includes an amount and currency but no due date. The result preserves the missing field instead of filling it in.

Output artifact

record.json

Saved locally for you to inspect and use.

main.kujo

Source ↓
from common import load, save, config, request, require_result

let input := load("input.json")
let result := request(config(), "Extract invoice fields from the text. Use null for an absent due date. Copy an exact evidence quote for the amount; never invent missing facts.", input, "responses.json", load("schema.json"))
let data := require_result(result)
assert(contains(input["text"], data["invoice"]), "Invoice ID is not grounded")
assert(contains(input["text"], data["evidence"]), "Evidence is not in the document")
assert(contains(data["evidence"], data["currency"]), "Currency is not in the evidence")
assert(contains(data["evidence"], to_string(data["total"])), "Amount is not in the evidence")
assert(data["due_date"] == null || contains(input["text"], data["due_date"]), "Due date is not in the document")
mut missing := []
if data["due_date"] == null { missing = push(missing, "due_date") }
save("record.json", {"record": data, "missing_fields": missing, "ready_for_review": true, "attempts": result["attempts"]})
print("Saved record.json with evidence and missing fields.")

Run it locally

Start offline.

Install Kujo, download the application, then run these commands from your download directory.

unzip document-extraction.zip -d document-extraction
cd document-extraction
kujo run main.kujo

The ZIP includes main.kujo, common.kujo, input, schema, response fixtures and README.md. Run inside its extracted directory. No key or network request is needed in offline mode.

Read the shared request policy ↗

Offline responses are authored test fixtures. They demonstrate control flow, not live model quality.

How it works

  1. Extract a record under a JSON schema.
  2. Require the invoice ID and amount evidence to occur in the source text.
  3. Report missing fields for a person to resolve.

Try a failure. Then recover.

Change the returned amount to 999 while leaving its evidence unchanged. The grounding check stops the run. Restore the fixture and rerun; the result again reports the absent due date.

Use a fresh extraction to restore the original fixtures. A failed run does not make an older output file current; check the exit status before consuming results.

Connect a live provider

Live mode sends your input to the configured provider and may cost money. Choose an OpenAI-compatible endpoint and model you can access, then set credentials in your environment. The example sends at most 1,024 output tokens per request and normally allows two attempts. The batch and regression examples apply that limit per item.

export KUJO_WORKFLOW_MODE=live
export KUJO_AI_ENDPOINT=https://your-provider.example/v1/chat/completions
export KUJO_AI_MODEL=your-model
# Set KUJO_AI_KEY securely in your environment.
kujo run main.kujo

Live transport was tested against a controlled local HTTP server, including failure and timeout cases. No paid provider call or claim about model quality is part of this demo.

Make it yours

Replace input.json.text with extracted document text and change the schema and grounding checks together. This example starts with text; PDF OCR and image extraction are separate steps.

Know the boundary

Substring evidence checks are intentionally small and inspectable. Repeated amounts and ambiguous invoices need stronger field-to-span validation and human review.
