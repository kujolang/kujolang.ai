What is a Kujo factory?

{{body}}

A factory connects a bounded input, specialized roles, executable checks and a local review package. The mechanisms differ by product. A successful test is not a formal proof; a hash identifies bytes; a model review is not human approval.

Kujo is the programming language and runtime. These factories demonstrate how its components can support practical work. You can also use individual tools, workflow contracts and agent guidance without adopting a factory.

One launch, five stations

Product Launch Factory verifies source evidence, then coordinates three domain factories and a launch review. Software Factory remains separate: this release can verify its export, but does not run an application-building stage.

  1. Source evidence

    Verify the incoming software export or WebOps package.

  2. Publishing House

    Draft, review and adapt the sourced campaign.

  3. WebOps

    Inspect the static page and retain bounded repair evidence.

  4. VideoOps

    Render the registered media into a video candidate.

  5. Launch review

    Collect exact versions and stop for human review.

Changing an input or packaged file invalidates its reviewed version. Completed handoffs can be reused only while their hashes still match. Watch the approved coordinator demonstration.

Start with a bounded example

  1. Choose a domain and read its prerequisites and limitations.
  2. Clone the repository and run the documented local checks.
  3. Inspect recorded evidence where supplied. A replay makes no new model calls.
  4. Authorize a live run only after reviewing the brief and provider usage.
  5. Inspect the candidate, source evidence and review records before deciding what to do with it.

For a coordinated launch, start with existing product evidence and the Product Launch setup guide. For application construction, use Software Factory and a reviewed software pack.
