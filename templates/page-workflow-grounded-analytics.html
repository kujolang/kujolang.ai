Explain computed metrics

Compute sales totals in code and check the numbers returned by the model.

Offline demo + live modeDownload application ↓

What you will build

Three orders total 9,000 cents. Code calculates the total; the model writes an explanation that must repeat the same count and amount.

Output artifact

analysis.json

Saved locally for you to inspect and use.

main.kujo

Source ↓
from common import load, save, config, request, require_result

let input := load("input.json")
mut seen := []
mut total := 0
for order in input["orders"] {
    assert(!contains(seen, order["id"]), "Duplicate order ID")
    seen = push(seen, order["id"])
    let checked := json_schema_validate(order["total_cents"], {"type": "integer", "minimum": 0})
    assert(checked["valid"], "Amounts must be nonnegative integer cents")
    total = total + order["total_cents"]
}
let metrics := {"order_count": len(seen), "total_cents": total}
let result := request(config(), "Explain these computed sales metrics. Copy their numeric fields exactly; do not infer trends from a single total.", metrics, "responses.json", load("schema.json"))
let data := require_result(result)
assert(data["order_count"] == metrics["order_count"], "Model changed the order count")
assert(data["total_cents"] == total, "Model changed the computed total")
save("analysis.json", {"metrics": metrics, "explanation": data["explanation"], "status": "needs_review"})
print("Saved analysis.json with checked numeric fields.")

Run it locally

Start offline.

Install Kujo, download the application, then run these commands from your download directory.

unzip grounded-analytics.zip -d grounded-analytics
cd grounded-analytics
kujo run main.kujo

The ZIP includes main.kujo, common.kujo, input, schema, response fixtures and README.md. Run inside its extracted directory. No key or network request is needed in offline mode.

Read the shared request policy ↗

Offline responses are authored test fixtures. They demonstrate control flow, not live model quality.

How it works

  1. Validate unique order IDs and nonnegative integer amounts.
  2. Compute the order count and total locally, then send only those metrics.
  3. Reject model numbers that disagree with the calculation.

Try a failure. Then recover.

Change total_cents in the response fixture to 9999. The comparison rejects it. Restore 9000 and rerun to recover.

Use a fresh extraction to restore the original fixtures. A failed run does not make an older output file current; check the exit status before consuming results.

Connect a live provider

Live mode sends your input to the configured provider and may cost money. Choose an OpenAI-compatible endpoint and model you can access, then set credentials in your environment. The example sends at most 1,024 output tokens per request and normally allows two attempts. The batch and regression examples apply that limit per item.

export KUJO_WORKFLOW_MODE=live
export KUJO_AI_ENDPOINT=https://your-provider.example/v1/chat/completions
export KUJO_AI_MODEL=your-model
# Set KUJO_AI_KEY securely in your environment.
kujo run main.kujo

Live transport was tested against a controlled local HTTP server, including failure and timeout cases. No paid provider call or claim about model quality is part of this demo.

Make it yours

Replace the orders with your own records and keep money in integer minor units. Add deterministic calculations for new metrics before asking the model to explain them.

Know the boundary

The numeric fields are checked, but the prose may still mislead. Review the explanation before sharing it. This example does not generate or execute SQL.
