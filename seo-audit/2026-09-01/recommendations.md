# Recommendations and measurement plan

Audit started: 2026-09-01. Deployment verification: 2026-09-02.

## Immediate after deployment

- Inspect `/ecosystem/ability/` and the updated sitemap in Google Search Console and Bing Webmaster Tools when access is available.
- Add a release annotation in analytics and preserve the deployment timestamp.
- Confirm the social preview once on each target network; do not regenerate the deterministic asset unless a platform reports a real rendering defect.
- Publish, replace, or remove the inaccessible Leash and Ward repository links; do not expose a private repository merely to satisfy the crawl.

## 7-day checks

- Record index state, impressions, clicks, query terms, referrals, and crawl errors for the Ability URL.
- Run the same technical crawl and compare only observed deltas.
- Capture any AI-answer mention or citation with platform, date, prompt, cited URL, and screenshot or export.

## 28-, 60-, and 90-day comparisons

- Compare impressions, clicks, click-through rate, average position, non-brand discovery, referral traffic, and conversions against the launch annotation.
- Review which reciprocal page supplies useful internal referrals and whether visitor behavior supports a stronger navigation placement.
- Re-run the fixed AI-search benchmark only on explicitly available surfaces; do not infer visibility from ordinary search results.
- Review Core Web Vitals and real-user image performance when field data is available.

## Editorial decisions

- Keep the page aligned with released Ability behavior; update it only when a shipped version changes the contract, host support, or execution boundary.
- Leave the writing section unchanged until the planned content push.
- Treat a hosted privileged Ability gateway as its own product launch with security, identity, tenancy, support, and reliability evidence—not as a copy change to the current page.
