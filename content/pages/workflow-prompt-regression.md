<section class="workflow-section"><h2>How it works</h2><ol class="workflow-steps"><li>Run both prompts over the same labeled cases.</li><li>Record predictions, per-case correctness and prompt hashes.</li><li>Exit with a failed gate if the candidate passes fewer cases.</li></ol></section>
<section class="workflow-section workflow-failure"><h2>Try a failure. Then recover.</h2><p>Change both candidate response fixtures to technical. The candidate regresses and exits 4. Restore the original fixtures and rerun to recover.</p><p>Use a fresh extraction to restore the original fixtures. A failed run does not make an older output file current; check the exit status before consuming results.</p></section>
<section class="workflow-section"><h2>Connect a live provider</h2><p>Live mode sends your input to the configured provider and may cost money. Choose an OpenAI-compatible endpoint and model you can access, then set credentials in your environment. The example sends at most 1,024 output tokens per request and normally allows two attempts. The batch and regression examples apply that limit per item.</p><div class="sample-code"><pre tabindex="0"><code>export KUJO_WORKFLOW_MODE=live

<section class="workflow-section"><h2>Make it yours</h2><p>Add representative cases and expected labels to input.json. Use live mode to collect actual model results, repeat runs and review errors before changing a production prompt.</p><h3>Know the boundary</h3><p>The offline score tests the evaluation machinery with authored responses. Two cases are not evidence of general prompt quality. Live results may vary even with temperature zero.</p></section>
