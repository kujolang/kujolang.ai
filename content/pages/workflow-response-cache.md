<section class="workflow-section"><h2>How it works</h2><ol class="workflow-steps"><li>Hash the input, prompt, schema, mode, provider identity and request code.</li><li>Validate a matching cache entry before using it.</li><li>Write a complete replacement cache after a successful request.</li></ol></section>
<section class="workflow-section workflow-failure"><h2>Try a failure. Then recover.</h2><p>Run twice, deleting responses.json after the first run. The second run succeeds from cache. Change prompt_revision in input.json and it must request again; restore responses.json from the ZIP to recover.</p><p>Use a fresh extraction to restore the original fixtures. A failed run does not make an older output file current; check the exit status before consuming results.</p></section>
<section class="workflow-section"><h2>Connect a live provider</h2><p>Live mode sends your input to the configured provider and may cost money. Choose an OpenAI-compatible endpoint and model you can access, then set credentials in your environment. The example sends at most 1,024 output tokens per request and normally allows two attempts. The batch and regression examples apply that limit per item.</p><div class="sample-code"><pre tabindex="0"><code>export KUJO_WORKFLOW_MODE=live
export KUJO_AI_ENDPOINT=https://your-provider.example/v1/chat/completions
export KUJO_AI_MODEL=your-model
# Set KUJO_AI_KEY securely in your environment.
kujo run main.kujo</code></pre><button type="button" class="sk-button code-copy-icon" data-copy-code aria-label="Copy code" title="Copy code" hidden><svg viewBox="0 0 24 24" width="20" height="20" fill="none" stroke="currentColor" stroke-width="1.6" aria-hidden="true"><rect x="8" y="8" width="12" height="12" rx="1.5"/><path d="M16 8V4H4v12h4"/></svg></button><span role="status" data-code-status></span></div><p>Live transport was tested against a controlled local HTTP server, including failure and timeout cases. No paid provider call or claim about model quality is part of this demo.</p></section>
<section class="workflow-section"><h2>Make it yours</h2><p>Change prompt_revision when policy changes. The key also covers the prompt and request code automatically. Use one trusted writer per directory and delete cache.json when you want a fresh result.</p><h3>Know the boundary</h3><p>This local cache has no expiry or cross-process lock. It excludes credentials from the key, so use separate directories for different accounts or tenants. Model behavior can change under the same model name; invalidate the cache when that matters.</p></section>
